Como ler o manual

Rótulos reais

O que está em destaque azul é o texto de botões e campos exatamente como aparece na tela. Caminhos de menu aparecem assim: Configurações›Geral.

Números e setas

Um círculo numerado é um passo, na ordem. Nas telas desenhadas, o número no canto de um elemento é o item da legenda ao lado.

Tipos de aviso

Dica ou contexto.

Atenção.

Não tem volta.

As telas são desenhos simplificados, não capturas: servem para mostrar onde cada coisa fica e continuam valendo quando a aparência muda. Se algo não estiver neste manual, ele não afirma que existe.

1

Começando

Instalar uma vez, parear o navegador e criar o primeiro projeto.

Requisitos

  • Node 22 ou mais novo
  • Git
  • Windows 10/11 ou Linux

Instalar e abrir

  1. Clone o projeto no terminal.

  2. Entre na pasta.

  3. Rode o setup. Ele roda uma vez só.

O npm run setup faz tudo isto:

  1. Instala

    as dependências.

  2. Instala

    o Claude Code e o login, se faltarem.

  3. Oferece

    as barras de consumo.

  4. Abre o navegador

    já pareado, no endereço local do Claudio’s Club.

Depois disso, use tudo pelo navegador.

Ligar de novo

Computador reiniciado, por exemplo. Há dois caminhos:

1. Botão Iniciar

Na página de início, que aparece no mesmo endereço quando o Claudio’s Club está parado.

O botão chama o link myco://. Na primeira vez, o navegador pergunta se pode abrir: marque sempre permitir.

2. Pelo terminal

Se o botão Iniciar não fizer nada, rode esse comando uma vez: ele registra o link e sobe o Claudio’s Club.

Segundo plano

O trabalho roda no servidor do Claudio’s Club (um processo Node na sua máquina, porta 4848), não no navegador. Fechar a aba ou o navegador não para os funcionários: as conversas em andamento terminam o turno, a fila anda, e revisões, despertadores e continuações agendadas seguem.

O que precisa de você (aprovar permissão, aprovar ou recusar plano, mover card, responder pergunta) continua esperando até você abrir o Claudio’s Club de novo.

Para de verdade só se você fechar o servidor (terminal ou processo), clicar em Parar o Clube dos Claudios (Configurações → Geral → Servidor), ou se o computador hibernar ou desligar.

Parear o navegador

As ações (mandar mensagem, botões) só funcionam em navegador pareado. Num navegador novo:

  1. Clique em Parear este navegador, no aviso que aparece. Ou vá em Configurações›Geral›Pareamento deste navegador.

  2. A tela mostra um comando com um código. Rode npm run pair CÓDIGO num terminal seu, na pasta do Claudio’s Club, e confirme.

  3. Pronto: a aba se pareia sozinha.

    • O código vale 10 min
    • O pareamento dura 1 ano

Os funcionários não conseguem aprovar o pareamento: quem aprova é o terminal do usuário.

Escolher o nível de uso

Configurações›Geral›Nível de uso

Simples

Contratar só com nome e cargo (o resto vem do cargo). O essencial na tela.

Avançado

Todos os campos da ficha, do painel e das configurações.

Dá para trocar a qualquer hora; nada se perde.

Ver o projeto demo opcional

Para ver uma equipe pronta, numa pizzaria de exemplo (My.Co), com landing, cardápio e pedidos:

  1. Abra Configurações›Geral›Projeto demo.

  2. Clique em Criar projeto demo. Ele cria uma vez e abre a sala.

Ver o quadro e as fichas não gasta nada. Abrir um funcionário usa a sua cota.

Primeiro projeto

  1. No canto de baixo do quadro, clique em + projeto. Ele cria ou abre um projeto já na aba em que você está.

  2. Escolha como: Criar pasta nova (preencha Nome da pasta e Onde criar) ou Pasta que já existe (preencha Caminho da pasta).

  3. Marque, se quiser: Iniciar um repositório git (o painel de código e a revisão usam o diff).

  4. Clique em Criar projeto (pasta nova) ou Abrir projeto (pasta existente).

A pasta entra no quadro na hora. O Claude Code passa a conhecê-la na primeira conversa.

Trazer um projeto que você já usou com o Claude Code

  1. Clique

    + projeto → Importar do Claude Code

  2. Marque

    os projetos que quer trazer.

  3. Clique

    Importar (n)

Nada muda nas pastas deles.

Depois do projeto, contrate o primeiro funcionário.

Workspaces

Workspace é um grupo de projetos (por cliente, área, pessoal etc.). Cada workspace vira uma aba no quadro, com cor e fundo próprios.

Criar

  1. Configurações›Quadro›Workspaces

  2. Digite em Nome do workspace e clique em Adicionar.

  • Renomear: edite o nome no cartão do workspace. Ele salva quando você sai do campo ou aperta Enter.
  • Fundo: Fundo do quadro nesta aba, no cartão do workspace (uma cor para cada tema).
  • Pôr um projeto num workspace: abra o projeto e, no campo Workspace, escolha o nome. Para tirar, escolha Sem workspace.
  • Remover: o botão Remover no cartão. Os projetos dele ficam Sem workspace; nada é apagado.

Numa aba vazia, o quadro diz: “Nenhum projeto nesta aba. Ponha um pelo detalhe do projeto ou crie um novo.”

Não abre ou a tela fica em branco

Rode npm run doctor: ele aponta o passo com problema e o comando de correção. Os casos mais comuns:

SintomaO que fazer
Tela em branco, sem erro no consolenpm run build
Build falha com Failed to resolve entry for packagenpm ci, depois npm run build (o npm install não conserta)
O botão Iniciar não faz nada, ou o Windows oferece a Microsoft Storenpm run daily:start uma vez
Ações dizem que o navegador não está pareadoClique em Parear este navegador e rode o npm run pair CÓDIGO que aparece. Use sempre o mesmo endereço (claudio.localhost)

Se o problema não estiver aqui, rode npm run doctor: ele só lê e mostra o que falta.

Funcionários

Contratar, entender a ficha e organizar a equipe.

Contratar

Pelo quadro: o +

  • Clique no + do projeto

    O novo funcionário reporta a você.

  • Clique no + de um funcionário

    O novo reporta a ele.

  • Arraste o + e solte no vazio

    Abre as mesmas opções do clique.

  • Arraste o + de um funcionário sobre um colega do mesmo projeto

    Liga os dois: o gestor passa a chamar o colega.

  • Solte sobre um funcionário de outro projeto

    Copia a ficha dele para este projeto (pede confirmação).

  • No celular

    O toque faz o mesmo.

Do zero ou da empresa

  • No formulário, escolha Do zero (ficha nova) ou Da empresa (copia a ficha de outro projeto).
  • Em Da empresa, busque por nome, cargo ou projeto e clique em Copiar para este projeto. A cópia entra como funcionário novo; a ficha original não muda.
  • Marque Levar a memória também se quiser levar a memória. Ela pode ter detalhes do outro projeto.

No nível simples

  1. Escolha o cargo nos botões. Já vem marcado o cargo padrão, se houver; senão, o Orquestrador(a).

  2. Preencha Nome* e, se quiser, Retrato.

  3. Clique em Contratar.

  • Ele nasce sem MCPs. Para os outros campos, clique em Mostrar todos os campos.
  • A conversa abre vazia. A primeira tarefa você manda pelo chat (ver Conversar).

Mudar o modelo de um cargo

Configurações›Cargos (Cargos para contratar)

  • editar: muda o modelo.
  • padrão: o que já vem marcado ao contratar.
  • tirar ou voltar ao original.
  • Novo cargo, e salve com Salvar cargo.

A mudança vale para os próximos contratados.

A ficha

Abra o funcionário e, no painel dele, clique em ⋯ (Mais opções). As abas são Ficha (quem é) e Projeto (o que usa e como trabalha no projeto).

Aba Ficha

  • Nome* e Cargo*: nome e cargo na ficha. Retrato: foto pequena, mostrada no quadro.
  • Missão*: o que ele faz. A primeira frase é o que o gestor vê dele. Depois, Definição de pronto e Regras (uma por linha).
  • Modelo e Esforço: começam do cargo.
  • Roteiro: Nenhum (trabalha do jeito dele), Planeja grande, executa pequeno, Reconhece, depois constrói ou Portão de revisão.
  • Autonomia: veja abaixo.
  • Trabalhar numa worktree própria: cópia git só dele, num branch próprio. O projeto precisa ser repositório git.
  • Pode contratar subfuncionários: os contratados entram como temporários, com no máximo a autonomia dele.
  • Motor e Motor secundário aparecem só com o Codex ligado (ver Consumo e motores).

Aba Projeto

  • Reporta a: quem pode chamá-lo. Nenhum marcado = só você.
  • Conhecimento (um caminho por linha): arquivos que ele lê antes de começar. Agents e skills indicados aparecem se o projeto tiver algum.
  • MCPs: marque os que ele usa (ver MCPs).
  • Servidores (SSH e FTP): clique em + dar acesso a servidores (SSH e FTP) e marque as conexões que ele pode usar. A chave fica no seu computador; a ficha guarda só o nome da conexão.
  • Usar o navegador (Claude in Chrome): usa o seu Chrome, com os seus logins. Envios, compras e formulários pedem o seu ok. Precisa da extensão instalada.

Salve com Salvar ficha (ou Contratar, ao criar). Cancelar fecha; no painel, o botão é Desfazer. Mudanças na ficha e nos MCPs valem a partir da próxima sessão.

Autonomia

Campo Autonomia, na aba Ficha. São cinco opções:

Só planeja

Lê e propõe; não altera arquivos nem roda comandos.

Pede tudo

Pede aprovação antes de cada edição ou comando.

Edita sozinho

Edita arquivos sem perguntar; pede antes de rodar comandos.

Autônomo

O Claude Code decide o que é seguro rodar; o que julga arriscado (deploy em produção, apagar em massa) é recusado e ele pede a você.

Sem travas

Não pede nada. Os bloqueios de segredos (.ssh, .env) e os hooks continuam. Só para quem você confia, em projeto com git.

Memória

Cada funcionário tem uma memória própria, que atravessa as conversas: decisões e o porquê, convenções, pendências e onde parou. Ela é curta (cerca de 60 linhas).

  1. Começa a conversa

    Ele lê a ficha e a memória.

  2. Trabalha

    Com o que está na ficha e na memória.

  3. Fecha um assunto

    Ele atualiza a memória.

Memória pessoal

  • Na ficha de quem já existe, a seção Memória pessoal tem o botão Editar a memória pessoal.
  • Ela vale em todos os projetos da pessoa, só para o que serve de um projeto para o outro.
  • Tem limite de linhas e de bytes; se passar, resuma antes de Salvar memória.

O funcionário lê a memória pessoal, mas não a altera. Se ela estiver errada, edite-a na ficha ou peça ao funcionário que aponte o erro.

Gestor e equipe

  • Reporta a define quem chama quem. Só quem tem Pode contratar subfuncionários contrata.
  • Um subordinado nunca tem mais autonomia que o gestor.
  • Um gestor repassa o que é da área de cada subordinado como tarefa (aparece no quadro de tarefas). O que não tem dono ele faz ou passa aos agents.
  • Temporários saem do quadro quando terminam. Nada é apagado.

Organograma (quadro)

  • Cada projeto é uma sala; os funcionários ficam dentro dela. As linhas entre eles mostram empresta e delegando.
  • Para desfazer um vínculo, clique em Desfazer vínculo na linha entre os dois. A ficha anterior fica no histórico.
  • Reorganizar o quadro (botão do canto do quadro) desfaz os arrastos e refaz a grade de salas mantendo a ordem de agora (de cima para baixo, da esquerda para a direita) dentro de cada workspace.

Legenda do quadro:

  • projeto
  • funcionário / agent
  • skill

RH

  • Botão RH na barra do topo (título Funcionários): uma linha por pessoa, com um chip por projeto em que ela tem ficha.
  • Clique na linha ou num chip para editar. Filtre pela busca ou por Projeto.
  • Se houver ficha de mesmo nome em outro projeto, aparece Unificar (“É a mesma pessoa?”). Ele pede confirmação com Juntar.
  • Em ⋯ (ações da pessoa): Ligar a outra ficha, Arquivar ou Desarquivar por projeto, Separar deste projeto (se estiver em mais de um) e Excluir.

Excluir apaga ficha, memória, foto e histórico de vez. Se houver tarefas abertas, o sistema avisa e elas ficam sem responsável.

MCPs

Configurações›MCPs (Servidores MCP). Há quatro escopos:

Da conta (Club) recomendado

Segredos no cofre do sistema, e só quem tem o MCP na ficha carrega.

Da conta (Claude Code)

Todas as sessões do Claude Code veem.

Do projeto

Vai para o git: não ponha chave ali.

Locais do projeto

Só neste computador.

  • Tipos: HTTP, SSE e Comando local.
  • Valores de variáveis e cabeçalhos nunca voltam para a tela: aparece “definido”.
  • Botões: + MCP, Testar, Editar, Excluir.

Conversar com o funcionário

Mandar mensagens, responder o que ele pede e controlar a conversa.

Mandar mensagem

  1. Clique no funcionário no quadro. O painel dele abre com a conversa.

  2. Escreva na caixa e aperte Enter. Shift+Enter quebra a linha. Digite / no começo para os comandos da sessão, ou @ para os arquivos do projeto.

  3. O botão de envio faz o mesmo que o Enter.

  4. Numa conversa nova, a tela diz: “Comece a conversa: [nome] lê a ficha e a memória antes de responder.”

Enquanto ele trabalha

Você pode mandar mensagem no meio do trabalho. O que acontece depende de Configurações›Conversa›Mensagem durante o trabalho (vale para todos os funcionários).

  • Enviar

    entra no meio: entra entre uma ferramenta e outra, sem parar.

  • Pôr na fila

    vai para a fila: espera ele terminar e vira a próxima mensagem.

  • Enviar agora

    interrompe: interrompe o que ele está fazendo e responde já.

  • Parar interrompe o turno atual.
  • Uma linha discreta acima da caixa mostra o que ele está fazendo agora.
  • O chip N em segundo plano lista os agents e comandos que estão rodando. Clique para ver e parar cada um.

Anexos

  • Anexar arquivo, ou cole com Ctrl+V. Aceita imagem, texto e PDF.
  • Imagens são reduzidas no navegador antes de ir.
  • até 4 imagens por mensagem
  • até 5 arquivos
  • PDF até 2,9 MB
  • texto até 200 KB

Arquivo de outro tipo não entra e a tela avisa assim.

Ajustes desta conversa

  1. A barra logo abaixo da caixa tem modelo, esforço e autonomia só desta conversa. Vale na hora; a ficha não muda.
  2. Ícone de MCPs (só no nível avançado, com a conversa rodando): liga e desliga MCPs só nesta conversa.
  3. Compactar: resume o início da conversa para liberar contexto. O anel ao lado mostra o quanto do contexto está em uso (o número aparece ao passar o mouse).
  4. Ícone O que mudou: os arquivos que ele mudou, o diff, os testes e, na worktree dele, mesclar.

Chat detalhado (Configurações›Conversa) mostra as leituras, buscas e comandos que ele fez. Sem ele, a conversa mostra só as mensagens, os pedidos de permissão e os avisos.

Precisa de mim

  1. O botão precisa de mim fica no topo do quadro, com um contador.

  2. Clique para abrir a lista.

  3. Clique num item para abrir a conversa dele.

RótuloQuando aparece
planoTem um plano para você aprovar.
permissãoPede permissão para uma ação.
segredoRecebeu um segredo no chat. Botões: já troquei e não é segredo.
esperandoEspera sua resposta.
erroParou com erro.
rotinaUma rotina não rodou.
sem donoFicou sem dono num reinício.
  • Pergunta, espera e rotina têm um × para tirar o item da caixa. Ao tirar uma pergunta, ela sai sem resposta (“Tira da caixa sem responder agora”). Ao tirar uma espera, ela só sai da caixa até a sessão mudar de status.
  • Se nada espera você, a lista diz: “Nada espera você agora.”
  • A caixa tem a opção avisar no sistema (inclusive quando alguém termina).

Permissão, plano e pergunta

Três cartões aparecem na conversa quando o funcionário precisa de você. Cada um tem os seus botões.

Permissão

  • Aprovar: vale só para este pedido.
  • Sempre nesta conversa: não pergunta mais isso nesta conversa.
  • Sempre neste projeto: libera de vez no projeto.
  • Negar.
  • Perguntas com opções não têm os botões “Sempre”.

Plano

  • Aprovar e executar: executa com a autonomia da ficha. Se a ficha for Só planeja, executa como Edita sozinho.
  • Pedir mudanças: ele continua só planejando. Escreva o que mudar.
  • Recusar plano: não executa e tira a tarefa da fila (vai para Aguardar).

Pergunta

  • Escolha a resposta (ou Outra resposta…) e clique em Responder. Se disser “pode marcar mais de uma”, marque quantas quiser.
  • Pular: segue sem responder. Ele fica sabendo que você não respondeu.

Arquivo citado vira link

  1. A resposta cita um arquivo

    com o caminho relativo entre crases, por exemplo src/app.ts:42.

  2. O caminho vira link

    Clique para abrir no editor de arquivos.

Se não virar link, o caminho aparece só como texto.

Despertador

  • Para acompanhar algo que demora (deploy, CI, um site), o funcionário pode pedir para voltar a olhar depois, entre 10 s e 24 h.
  • Só um despertador por conversa. Agendar de novo troca o anterior.
  • O aviso mostra a contagem regressiva e Cancelar.

Tarefas

Um pedido de trabalho para um funcionário, com conversa própria. O quadro mostra em que pé cada uma está.

Abrir o quadro

  • No painel do projeto, botão Tarefas. No nó do projeto no quadro, o selo de tarefas em revisão também abre.
  • O título é “Tarefas · {nome do projeto}”. O quadro relê as tarefas a cada 5 segundos.
  • Fecha pelo × ou com Esc. Com um cartão aberto, Esc fecha só o cartão.
  • No cabeçalho: Agendamentos (ver cap. 5) e Nova tarefa.

Colunas

ColunaO que quer dizer
AguardarParada. Não começa sozinha nem entra na fila. O campo Motivo (opcional) fica no cartão.
A fazerNa fila. Começa sozinha quando o funcionário entrega a atual.
FazendoTrabalhando. Inclui as tarefas com plano para aprovar (selo Plano para aprovar).
RevisãoEle terminou um turno. Confira a entrega.
ProntoEntregue e conferido.
  • Para mudar de coluna, arraste o cartão, ou no detalhe use Mover para a coluna (opções “mover: …”).
  • Em Pronto, tarefa sem mudança há mais de 7 dias vai para Ver arquivadas (n). Mudar de coluna tira do arquivo.
  • O selo Não publicado aparece em Pronto nos projetos com funcionário que tem servidor. Ele não some quando o deploy é pedido.

Criar tarefa

  1. Clique em Nova tarefa.
  2. Preencha Título (até 120 caracteres), O que precisa ser feito e Quem cuida.
  3. Opcional: marque Revisão automática e escolha Quem revisa (outro funcionário do projeto).
  4. Escolha o botão:
    • Criar e começar: cria e manda para ele numa conversa nova. Precisa de Quem cuida. Se ele estiver ocupado, a tarefa entra na fila dele.
    • Só criar: cria em Aguardar.
    • Cancelar: não cria nada.

Começar e fila

  • Cartão sem conversa: botão Começar. Com o funcionário ocupado, o botão vira Pôr na fila.
  • Cada funcionário faz uma tarefa por vez. A posição aparece no cartão (“na fila · 1ª”) e no detalhe. tirar da fila desfaz a entrada.
  • Mensagem sua na conversa de uma tarefa enquanto ele está ocupado fica guardada (“{n} ajuste esperando”) e vai quando ele termina.

Quando ele fica livre, o Club manda:

  1. Primeiro

    os ajustes guardados.

  2. Depois

    a próxima da fila.

Se o consumo estiver no limite na hora de começar, a tarefa fica na fila e tenta de novo.

Se a conversa parar no meio do trabalho (por exemplo, o servidor reiniciou), o Club retoma uma vez. Se parar de novo, a tarefa vai para Revisão com “conversa parou sem terminar” no histórico.

O responsável só pode ser trocado antes de começar. Depois, aparece “A tarefa já começou com este funcionário”.

Plano para aprovar

Se a ficha do funcionário está em Só planeja, ao começar a tarefa vai para Planejando. No quadro ela aparece em Fazendo, com o selo Plano para aprovar. Você decide no cartão de plano do chat:

  1. Ficha em Só planeja

    Você clica em Começar.

  2. Planejando

    Coluna Fazendo, com o selo Plano para aprovar.

  3. Você decide

    No cartão Plano pronto do chat.

Aprovar e executar

Vai para Fazendo e executa. O plano fica guardado no cartão (Plano aprovado).

Pedir mudanças

Continua só planejando. Escreva o que mudar.

Recusar plano

Não executa. A tarefa vai para Aguardar, e quem pediu a tarefa é avisado.

Entrega e revisão

  1. O turno dele termina

    Se o código está numa worktree, o Club faz um commit com o título da tarefa.

  2. Vai para Revisão

    Sozinha. Você confere o que mudou.

  3. Aprovar entrega

    Manda a tarefa direto para Pronto.

  • Mensagem sua na conversa da tarefa, com ela em Revisão, volta a tarefa para Fazendo.
  • A seção Código, revisão e deploy mostra o que mudou, o Resumo da entrega e o diff.

Aprovar entrega (em Revisão) não roda testes nem mescla.

Delegar revisão (manual)

Na seção Revisão, escolha Quem revisa e clique em Delegar revisão (ou Delegar nova revisão). O revisor responde com APROVADO ou REPROVADO na primeira linha. Ele não muda o código: só revisa.

APROVADO

Vai para Pronto. Se o código ainda está numa worktree sem mesclar, fica em Revisão (“aprovada; falta mesclar a worktree”).

REPROVADO

Os ajustes voltam para quem fez, e a tarefa volta para Fazendo. Se ele estiver ocupado, o ajuste fica guardado e a tarefa segue em Revisão.

Revisão automática

  • Com Revisão automática marcada, ao entregar, o revisor escolhido revisa sozinho, com o mesmo veredito.
  • O Club faz no máximo 2 revisões automáticas por tarefa. Depois disso, o que sobrar fica com você, anotado no histórico.
  • Precisa de outro funcionário no projeto. Se quem pediu a tarefa é o revisor, ele recebe só o resultado.

O cartão mostra n/3 e a opção diz “até 3 rodadas”, mas o limite que vale é 2.

Testes, mesclar e deploy

  1. Rodar testes

    Aparece se o projeto tem comando de teste (npm test, composer test ou phpunit). O cartão mostra Testes: “passaram” ou “falharam”. Se falhou, Saída dos testes mostra o fim do log.

  2. Mesclar em {base}

    Só com código em worktree. Pede confirmação, roda os testes e mescla. Teste vermelho desfaz a mescla. Sem teste para rodar, o Club pergunta se mescla mesmo assim. Depois, a tarefa vai para Pronto e mostra “mesclada em … (commit)”.

  3. Pedir deploy

    Em tarefa Pronto ou mesclada: escolha Quem faz o deploy (só quem tem servidor na ficha). O checklist pede backup, estado antes e depois, e runbook. Pede confirmação antes de qualquer passo que não tem volta.

Pedir ao Codex (segunda opinião) aparece só com Usar o Codex (GPT) ligado: ver cap. 6.

Editar, apagar e id

  • Editáveis: Título, Descrição, Quem cuida, Revisão automática, Quem revisa e PR (link https). O botão Salvar aparece quando título, descrição ou PR mudam.
  • Apagar tarefa pede confirmação. A conversa continua com o funcionário.
  • Se o funcionário é excluído, as tarefas abertas dele ficam sem responsável (“responsável excluído” no histórico).
  • O ID da tarefa aparece no cartão e no topo do detalhe: t- seguido de 6 caracteres hexadecimais. É o código para citar numa dúvida.
  • Histórico lista cada mudança, marcada como “automático” ou “você”.

Agendamentos e arquivos

Agendamentos

Abra pelo botão Agendamentos, no cabeçalho do quadro de tarefas. O título é “Agendamentos · {projeto}”. A tela diz: “O que os funcionários deixaram marcado para fazer sozinhos. Cancele o que não deve acontecer.”

Despertador

Pedido pelo próprio funcionário. Na hora marcada ele recebe a mensagem e volta ao trabalho.

Continuar após o limite

Automático. O limite de uso da assinatura acabou no meio de uma conversa. O “continue” é enviado quando o limite voltar.

  1. Quem: o nome do funcionário (Freela para conversa sem ficha).
  2. Quando: “às HH:MMh” (com a data se for outro dia) e a contagem regressiva (“em 4min 05s”, “agora”).
  3. O texto do despertador, ou “(sem mensagem)” se estiver vazio.
  4. Abrir conversa abre a conversa. Cancelar pede confirmação: Sim, cancelar ou Manter.

Avisos possíveis

  • Agendamento cancelado.
  • Esse agendamento já não existe (já aconteceu ou foi cancelado).
  • Não deu para cancelar: {erro}
  • Nenhum agendamento pendente.
  • A lista é relida a cada 5 segundos. Ver tarefas volta ao quadro.
  • Quando uma tarefa troca de motor (ver cap. 6), o despertador e o “continue” da conversa antiga são cancelados. A hora do despertador vai para o resumo da conversa nova.

Arquivos

Abra pelo botão Arquivos no painel do projeto (“Ver e editar os arquivos do projeto”). O título é “Arquivos de {projeto}”.

  1. À esquerda, a árvore. Clique numa pasta para abrir; clique num arquivo para editar.
  2. À direita, o editor.
  3. Salvar (ou Ctrl+S) grava o arquivo. Nada é salvo sozinho. O estado aparece ao lado: Salvando…, Salvo, Não salvo ou Erro ao salvar (clique em Tentar de novo).

Criar

  1. Clique

    Arquivo ou Pasta: abre um campo para o nome.

  2. Digite o nome

    Enter cria, Esc cancela.

  3. Onde cria

    Dentro da pasta selecionada, ou “na raiz do projeto”.

O nome não pode começar com / ou \ e não pode ter ...

Apagar

Selecione o item e clique na lixeira (“Apagar {caminho}”). Há confirmação. É permanente: não vai para a lixeira. Numa pasta, apaga tudo o que está dentro.

Não apaga: segredos (.env e parecidos), .git, node_modules e .myco, nem pasta que contenha algum deles.

Limites e casos especiais

Segredo

Aparece com cadeado e não abre: “Arquivo de segredo: aparece na lista, mas não abre aqui.”

Grande demais

Para editar, o limite é 1 MB: “Arquivo grande demais para editar aqui (mais de 1 MB).”

Binário e imagem

Binário não edita como texto. Imagem só aparece para ver, até 10 MB.

Conflito

Se o arquivo mudou no disco (por exemplo, um funcionário editou), nada é sobrescrito. Escolha:

  • Recarregar do disco;
  • Manter o meu e salvar por cima.
  • Saindo com mudança não salva, a tela pergunta: “Há mudanças não salvas. Sair e perder essas mudanças?”.
  • Fechar: × ou Esc.
  • No celular, uma coisa por vez. Para voltar à árvore, use ‹ Arquivos.

Mudanças sem commit

No quadro, o selo do projeto mostra {n} sem commit (ou limpo). Clique no selo para abrir “Sem commit em {projeto}”. Cada grupo é uma conversa que editou esses arquivos.

  1. Clique em Pedir commit.
  2. Clique em Confirmar. Vai à conversa dela um pedido fixo: commitar só os arquivos dela, nomeando-os no git add. O pedido proíbe git add -A e também push ou PR sem pedido seu.
  3. Aparecem Pedido enviado e Abrir conversa.
  • Se outra conversa também mexeu no arquivo, o item mostra “também mexido por …”. Nesse caso o pedido manda separar só os trechos dela.
  • Conversa sem ficha: só a lista, sem botão (“conversa sem ficha: só a lista”).
  • Sem dono: arquivos editados à mão ou em conversas antigas. Não tem botão, porque não dá para saber de quem são.
  • Atualizar relê a lista.

Revisão de custo

  2. Os achados aparecem por prioridade: Prioridade alta, Prioridade média e Prioridade baixa.
  3. Achados com caixa marcada têm ajuste que o Club sabe aplicar. As caixas vêm marcadas. Os demais são só sugestão.
  4. Aplicar sugestões (n) abre a confirmação “Isto vai mudar em {nome}:”. Use Confirmar e aplicar ou Voltar.

  • Aviso de contexto ignorado
  • Modelo pesado em implementação

  • Memória grande
  • Saídas de ferramenta grandes
  • Leituras repetidas
  • Agents herdando o modelo caro
  • Retrabalho

Ficha

Regra

Tarefa

  • “sem ajuste automático”: é só sugestão

  • Modelo, esforço e regras valem para todas as cópias da pessoa em outros projetos. A conversa aberta dela recebe o aviso de ficha atualizada.
  • Sem achados no período: “Nada a ajustar no período”.

Projeto do zero, com orquestrador e equipe pequena

Situaçãovocê tem uma ideia e ainda não tem pasta.

Quem contratarOrquestrador(a), depois Back-end e QA (testes).

  1. + projeto → Criar pasta nova → Nome da pasta e Onde criar → marque Iniciar um repositório git (o painel de código e a revisão usam o diff) → Criar projeto.

  2. Clique no + do projeto → Orquestrador(a) → Nome* → Contratar. Ele já vem com Pode contratar subfuncionários marcado.

  3. Clique no + do Orquestrador para contratar Back-end e QA (testes): eles passam a reportar a ele.

  4. Abra o Orquestrador e descreva o pedido no chat, com o resultado esperado.

Conferir no fim

  • o quadro mostra a sala com os três funcionários, ligados ao Orquestrador;
  • se o pedido for grande, ele mostrou o plano antes e esperou o seu ok;
  • o selo do projeto mostra o que ficou sem commit;
  • ele disse como ver funcionando (endereço, arquivo ou passo a passo).
2

Funcionalidade nova: plano, execução, revisão e mesclagem

Situaçãouma funcionalidade que mexe no servidor e na tela.

Quem contratarBack-end (executa), Front-end (tela, se precisar) e Revisor(a) de código (revisa).

  1. Na ficha do Back-end (aba Ficha), marque Trabalhar numa worktree própria → Salvar ficha. Sem worktree não aparece Mesclar.

  2. Para aprovar o plano antes, use Autonomia Só planeja na ficha dele. Com ela, a tarefa para em Fazendo com o selo Plano para aprovar.

  3. Abra Tarefas no painel do projeto → Nova tarefa → Título, O que precisa ser feito (com o critério de pronto), Quem cuida: Back-end → marque Revisão automática e Quem revisa: Revisor(a) de código → Criar e começar.

  4. No cartão do plano, leia e escolha Aprovar e executar, Pedir mudanças ou Recusar plano.

  5. Quando a tarefa for para Revisão, abra O que mudou e confira o Resumo da entrega e o diff. Clique em Rodar testes.

  6. Clique em Mesclar em {base} e confirme.

  2. Revisão

3

Corrigir um bug, com revisão antes de aceitar

Situaçãoalgo quebrou e você consegue descrever como reproduzir.

Quem contratarBack-end ou Front-end (corrige) e Revisor(a) de código (revisa).

  1. Tarefas → Nova tarefa → Título (“Bug: ...”).

  2. Em O que precisa ser feito, escreva os passos para reproduzir, o resultado esperado e o que acontece hoje. Peça um teste que reproduza o bug antes da correção.

  3. Quem cuida: o responsável → marque Revisão automática e Quem revisa → Criar e começar.

  4. Em Revisão, clique em Rodar testes e veja se passaram. Leia o diff.

  5. Se faltar algo, escreva na conversa da tarefa: ela volta para Fazendo.

  6. Aceite com Mesclar em {base}. Aprovar entrega só move para Pronto; não roda testes nem mescla.

Aprovar entrega

Só move para Pronto. Não roda testes nem mescla.

Mesclar em {base}

É com ele que você aceita.

Conferir no fim

  • o teste de reprodução falhava antes e passa agora;
  • o diff não tem mudanças fora do bug;
  • você sabe se o código foi mesclado ou só aprovado.
4

Revisão de segurança antes de publicar

Situaçãovai publicar uma versão com login, tokens, segredos ou rotas novas.

Quem contratarSegurança (AppSec) (parecer, sem correção). Quem corrige é o Back-end ou o Front-end responsável.

  1. Contrate Segurança (AppSec) pelo + do projeto (ou pelo + do Orquestrador, se ele for o gestor).

  2. Tarefas → Nova tarefa → Título (“Auditar autenticação e rotas novas”) → em O que precisa ser feito, delimite o escopo: o diff ou a área, não o projeto inteiro.

  3. Quem cuida: Segurança (AppSec) → Criar e começar.

  4. Leia o parecer: riscos por gravidade, arquivo:linha, correção sugerida e a área que corrige.

  5. Para cada risco que vale corrigir, crie Nova tarefa para o responsável, com o trecho do parecer.

  6. Depois da correção, use Delegar revisão com Segurança (AppSec) e confira só os riscos críticos e altos.

  1. Parecer

    Riscos por gravidade, arquivo:linha, correção sugerida e a área que corrige.

  2. Nova tarefa

    Uma para cada risco que vale corrigir, para o responsável da área.

  3. Delegar revisão

    Com Segurança (AppSec): só os riscos críticos e altos.

Conferir no fim

  • nenhum segredo foi colado no chat; se foi, troque-o e clique em já troquei no aviso segredo (em precisa de mim);
  • os riscos críticos e altos estão corrigidos e reconferidos;
  • as dependências com vulnerabilidade estão separadas entre produção e desenvolvimento.
5

Servidor e deploy com DevOps / SRE

Situaçãoum site ficou lento ou precisa de uma versão nova no ar.

Quem contratarDevOps / SRE (autonomia Pede tudo: pede permissão a cada passo).

  1. Contrate DevOps / SRE. Na ficha, aba Projeto, clique em + dar acesso a servidores (SSH e FTP) e marque a conexão. A chave fica no seu computador; a ficha guarda só o nome.

  2. Tarefas → Nova tarefa → O que precisa ser feito: “só diagnosticar, sem mudar nada” → Quem cuida: DevOps / SRE → Criar e começar.

  3. Em precisa de mim, aprove cada cartão de permissão com Aprovar. Evite Sempre neste projeto para comandos no servidor.

  4. Para publicar, abra a tarefa em Pronto (ou mesclada) → Pedir deploy → Quem faz o deploy: DevOps / SRE.

  5. Siga o checklist: backup, estado antes e depois, runbook. Confirme os passos que não têm volta.

  • backup
  • estado antes e depois
  • runbook

Conferir no fim

  • o backup foi feito antes do deploy;
  • o runbook diz o que mudou e como desfazer;
  • as imagens e os volumes das versões antigas foram removidos (regra do cargo).
6

Acompanhar algo que demora (despertador)

Situaçãoum CI ou um deploy leva vários minutos e você não quer ficar olhando.

Quem contratarnenhum. Use o funcionário que já cuida do assunto (DevOps / SRE ou Back-end).

  1. No chat dele, peça para voltar a olhar depois, por exemplo: “volte a olhar o CI em 20 minutos e me diga se passou”.

  2. O aviso mostra “Volta a olhar em HH:MMh” com a contagem e Cancelar.

  3. Para ver todos os agendamentos, use Agendamentos, no cabeçalho do quadro de tarefas.

  4. Quando ele voltar, a conversa mostra “Voltou a olhar às HH:MMh” e a resposta.

Conferir no fim

  • a hora e o texto aparecem em Agendamentos;
  • só há um despertador por conversa: agendar de novo troca o anterior;
  • depois de 20 despertadores seguidos sem você falar, ele pede o seu ok.
7

Segunda opinião do Codex numa decisão difícil

Situaçãoa tarefa já tem mudanças grandes (troca de biblioteca, mudança no banco) e você quer um segundo parecer.

Quem contratarnenhum. O Codex revisa o diff de uma tarefa; ele não revisa uma ideia sem código.

  1. Configurações → Geral → Usar o Codex (GPT). Se não aparecer, use Nível de uso Avançado. O Club instala o Codex se faltar.

  2. Na linha Codex, se estiver sem login, clique em Entrar no Codex e espere (até 3 minutos).

  3. Na tarefa com mudanças, na seção Código, revisão e deploy, clique em Pedir ao Codex.

  4. Espere (“O Codex está revisando… leva alguns minutos”) e leia O que o Codex achou.

  5. Compare com o parecer do Revisor(a) de código e decida você.

Conferir no fim

  • você sabe que o diff foi enviado à OpenAI e que gastou a cota do seu ChatGPT;
  • arquivos de segredo não foram enviados;
  • a decisão final é sua, não do Codex.

Gastar menos

Situaçãoo consumo de 5 h ou de 7 dias sobe rápido, ou um projeto consome demais.

Quem contratarnenhum. Ajuste as fichas que já existem. O Orquestrador(a) e o Arquiteto(a) (Opus, High) são os mais caros: use-os para dividir e planejar, não para tarefa simples.

  1. Ranking (topo do quadro) → aba Gastos → escolha o Período → lupa Analisar o custo de {nome}.

  2. Veja os achados por prioridade. Revise as caixas marcadas e clique em Aplicar sugestões (n) → Confirmar e aplicar.

  3. Na ficha, aba Ficha, ajuste Modelo e Esforço (valem a partir da próxima sessão). Tarefa simples não precisa de Opus.

  4. Configurações → Consumo → Orçamento por projeto e Trava de consumo: 5 horas / 7 dias. Passando da porcentagem, o Club pergunta antes de conversar.

  5. Configurações → Conversa → Conversa nova quando o assunto fecha → Seguir sozinho numa nova (recomendado).

  6. Dentro de uma conversa grande, clique em Compactar para liberar contexto. Para começar do zero, use + (Nova conversa) no painel do funcionário; a ficha e a memória continuam.

Conferir no fim

  • o anel de contexto da conversa baixou;
  • as barras 5h e 7d estão em verde (abaixo de 70%);
  • a ficha mostra o modelo e o esforço novos.

Dicas

  • Peça uma coisa por tarefa, com o critério de pronto em O que precisa ser feito.
  • Pedido grande: peça o plano antes e só então dê o ok.
  • Pedido vago: o funcionário faz até três perguntas; responda com opções concretas.
  • Ficha enxuta: poucas regras, só as que valem sempre (limite de 50).
  • Memória curta (cerca de 60 linhas): guarde decisões, convenções e pendências, não logs.
  • Segredos não vão para o chat, para a ficha nem para a memória. Para MCP com chave, use o escopo Da conta (Club); Do projeto vai para o git.
  • Autonomia mínima: comece com Só planeja ou Edita sozinho. Sem travas só para quem você confia, em projeto com git.
  • Projeto sem git não tem worktree, diff nem Mesclar: crie o repositório na hora de criar o projeto.
  • Confira O que mudou e rode Rodar testes antes de Mesclar em {base}.
  • Antes de Atualizar o Club, deixe a árvore limpa (commit ou git stash).
  • Mensagem durante o trabalho: Pôr na fila espera; Enviar agora interrompe.
  • Antes de tentar outro caminho, use Duplicar: a conversa original fica.
  • Voltar até aqui desfaz arquivos, não comandos (instalar, banco, git).
  • Revisor(a) e Segurança (AppSec) dão parecer; a correção vira tarefa nova para quem é da área.
  • Para mapear um projeto já existente, crie o agent Pesquisador (Haiku, só leitura) com Novo agent no painel do projeto e peça o mapa a ele.

Erros comuns

  • Mesclar em {base} não aparece

    A tarefa não está numa worktree. Marque Trabalhar numa worktree própria na ficha de quem executa (o projeto precisa ser git).

  • Aprovar entrega marcou Pronto, mas o código não entrou na branch

    Esse botão não roda testes nem mescla. Use Mesclar em {base}.

  • A revisão automática parou antes da última rodada

    O limite são 2 revisões automáticas, mesmo com o cartão mostrando n/3. Use Delegar revisão para o resto.

  • Atualizar está desligado

    Há arquivos do Club mudados à mão. Guarde-os com git stash e tente de novo.

  • Ações dizem que o navegador não está pareado

    Clique em Parear este navegador e rode o npm run pair CÓDIGO que aparece, sempre no mesmo endereço (claudio.localhost).

  • A conversa de um funcionário com motor Codex não abre

    Usar o Codex (GPT) está desligado. Ligue-o em Geral.

  • Turno parado: passou de… (ferramentas ou minutos)

    O turno bateu o teto por turno e parou. Mande uma mensagem na conversa para seguir, ou mova o card. Se o trabalho é longo de verdade, aumente Ferramentas por turno ou Minutos por turno em Configurações → Executar (0 desliga).

  • Funcionário diz que há muitas mensagens entre funcionários

    A conversa passou de 20 mensagens de funcionários em 30 min. Responda na conversa (sua mensagem zera a conta). Veja Freios contra laço.
